- 修复（官方路径，已验证）：Artemis 分辨率设 `1920x1080`
  （全局「设置 → 引擎管理」或每游戏覆盖键 `art_resolution`）→ 舞台 1920x1080，

## 追加：自研内核补齐「图像缓存 / 字体缓存 / 省电绘制」

- 前提：字符串实证官方 6 个 .so 都含这三个键 → 决定在 artemis-compat 里也实现。
- 实现：
  - `FONT_CACHE_SIZE` → `GlyphAtlas` 页预算改为运行时（`SetMaxPages`，bytes/4MB，1..64，0=缺省 6 页）。
  - `SURFACE_CACHE_SIZE` → **新增解码像素缓存**（此前无跨层缓存，每次 lyc 都重读+解码）；
    只缓存 CPU 像素、GL 纹理仍归图层 → 淘汰永远安全；LRU + 缺省 32MB。
  - `POWER_SAVING` → 帧循环限流 ~30fps（循环仍全速，只跳过 present）。
  - 新增 `EngineContext::PlatformInt`（ANDROID→WINDOWS→COMMON），预算在 `Start` 套用。
- 取证日志：`cache budgets: ...`、`display: stage=... sidecut=... power_saving=...`、
  `surface cache hit[n]:`。
- 回归：`tests/glyph_atlas_regressions.cpp` 加页预算用例，arm64 真机 `ok`。
- 真机：缓存命中 17 次；省电 300 帧 6s→12.5s（≈50→24fps）。
- App：三项也提为公共项，官方专属**只剩引擎版本+自动补丁**；提示文案三语言再改。
- 坑：每游戏覆盖键名要带 `_size`（`art_surface_cache_size`/`art_font_cache_size`），
  写成 `art_surface_cache` 会被白名单静默忽略。
- 已还原用户配置（全局 official、流星覆盖不变）并清理设备临时文件。

## 追加：修复自研内核文本字号偏大 1.45 倍（Japanese Version 真机定标）

- 现象：Japanese Version（Girl's Blossom Project）自研内核正文明显更大、发虚、溢出对话框、
  两行粘连；官方内核正常。两内核对话框几何完全一致 → 与舞台/视口无关，纯字号问题。
- 量化（同一句「友達と一緒に登校するはずだったのに〜っ！」，size=46）：
  官方墨迹宽 878px vs 自研 1317px = **1.50 倍**。
- 根因（`artemis-compat/src/render/compositor.cpp` 的 `SetText`）：
  1. 字号换算用 `stbtt_ScaleForMappingEmToPixels`（em 方框 = size），官方 = `ScaleForPixelHeight`
     （hhea asc−desc = size）。思源黑体 upem=1000 / hhea asc−desc=1448 → **1.448 倍**。
  2. advance 取整：官方**截断**，自研用 `lround`（1448 下 30 vs 31px）。
  3. 行推进/首行基线：改用 **typographic ascender × em 比例**（0.88×size），不是 asc−desc。
- 定标方法（可复用）：XOR 解出游戏字体 → 用仓库自带 stb_truetype.h 写排版探针，
  对 (分母 × 取整方式) 网格算墨迹宽，与截图实测对齐，唯一钉死"1448 + 截断"。
  （此前误判的"分母≈1500"是取整量化假象。）
- 修复后真机逐像素比对：行高 43/43、行宽 294/879、x 范围 [530,823]/[530,1408] 与官方**完全一致**；
  行距 61 vs 官方 60。回归：行距修复前后均无崩溃，天空场景/樱花场景正常推进。
- 已部署（sha256 校验一致，`.orig` 备份仍在），恢复用户配置（全局 official、本游戏 clean）。
- 文档：VNLingo `docs/dev/MEMORY.md` 新增 2026-10-11 条目；artemis-compat `AGENT.md` §4 加字号红线。

## 追加：修复「说话人名字层渲染成对白字形」（流星，真机）

- 现象：流星名字标签显示对白开头（如「はぁ、はぁっ。」）+ 笔画残缺，而非角色名。
- 排除：文本来源正确。`tag[trace]`、自打的 `print[name]`、`SetText[name] ... glyphs=4`
  都显示名字层收到的是 `無線` / `フィバナ`。
- 根因：`Compositor::LoadFont` 调 `DropGlyphGl()` 删掉全部图集页纹理，但**其它层**的
  `TextGlyph::tex` 仍持有这些 GL 纹理名；GL 复用该名字给新页后，名字层用自己的旧 UV
  采样到对白层的字形。流星名字用 Bold、正文用 Medium，每句换一次 face，故每句必现。
- 修复：`GlyphAtlas::Key` 加 `face`（compositor 按字体路径分配自增 serial）；
  `LoadFont` 不再 `DropGlyphGl()`。图集只在「页水位淘汰」和「`ReleaseGl`」清空。
- 验证：名字标签恢复「無線」；淘汰计数 0；Girl's Blossom 像素级无回归
  （行高 43/43、行宽 294/879、x 范围、行距 61 全对）；图集回归 arm64 ok。
- 新增诊断日志：`print[name]` / `SetText[name]` / `glyph atlas watermark eviction`。
- 遗留：页水位淘汰时仍会清空所有层 glyph（名字会空白），本次未触发；彻底解法需
  按引用重映射各层 glyph，或重估 `FONT_CACHE_SIZE → 页数`（现为 ÷4MB，对 RGBA 偏保守）。
- 配置已还原（流星 official + 1920x1080；Girl's Blossom clean；全局 official），设备已清理。

## 追加：修 Artemis 触摸模式手柄失效 + 两侧模式指示不一致（流星真机）

用户报三个现象：① 触摸模式手柄完全不能用 ② 手柄无法切到虚拟鼠标模式 ③ 刚进游戏模式偶尔
错乱、与右缘「点击模式」键图标不一致。查明是**四个独立缺陷叠加**：

1. **触摸模式按键整体丢失**（①②）：Artemis 是 NativeActivity 直读输入，而宿主加的覆盖窗
   （面板窗/光标窗/左右缘按键窗）**全是 FLAG_NOT_FOCUSABLE** → 没有窗口持焦 → 按键
   Java 与游戏都收不到。判据：同画面 `input tap` 点 START 正常，而 `input keyevent/gamepad
   keyevent` 零反应，`dumpsys window` 的 mCurrentFocus 却是 Activity 主窗口。
2. **`EmulateKeyEvent(id, 2)` 的 status 语义错**：内核 `InjectHostKey` 只按「status==0=down、
   非 0=up」入队 → 传 2 = 只发 UP、永无 DOWN → 转发链全废。修：新增 `tapEngineKey(id)`
   = 0 + 60ms 后 1，替换映射表 31 处。
3. **右缘「点击模式」图标不跟手柄切换刷新**（③一半）：`clickModeButton` 只在创建时与
   点它自己时更新。修：刷新器挂根视图 tag + `OnsSideButtons.refreshClickMode()`，
   面板在「手柄快捷键切换后」与「启动确定模式后」各刷一次。
4. **启动时光标可见性不同步**（③另一半）：只把模式读回字段，光标 `cursorVisible` 停在初始
   false（ONS 连初始化同步都没有）；且侧键在建 prefs 读取**之前**创建，图标定格初值。
   修：新增 `EngineOverlayRouting.syncCursor()`，三宿主接入 + 补刷图标。

顺带：Artemis 的 `routePanelKey`/`routeMouseKey` 调 `virtualMouse.handleKey` 漏了
`virtualMouseMode` 门控（统一路由有）→ 触摸模式下面板一展开，方向键/A 会被虚拟鼠标强行
点亮光标并吞键；`EngineVirtualMouse` 加 `needsRecenter`+`onSizeChanged` 修启动时光标落在 (0,0)。

**验证**：触摸模式游戏内发 ENTER → 画面推进 + 内核 `onpush: key=13`；触摸模式按键进 Java
（`mouse catcher key code=`）；R2 切模式成功（prefs false→true）；两种模式下光标与右缘图标一致。
**判据陷阱**：流星**标题菜单只认点击**，在那里按任何键都没反应 —— 别把它当成 bug，验按键要进对话。

`ONScripter.java`、`EngineOverlayRouting.java`、`EngineVirtualMouse.kt`、`OnsExtractPanel.java`、
