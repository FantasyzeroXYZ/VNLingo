# 安卓开发通用规范（跨项目统一）

> 适用范围：所有 Android 项目（VNLingo、Tyranor-Next 等）的通用工程规范。
> 项目特有约定见各项目自己的专门规范文档（如 VNLingo 的《VNLingo 项目规范》）。
> 违反"必须（MUST）"级条目的代码/脚本不得合入。

## 1. 文件编码与换行（最高频踩坑点）

| 文件类型 | 编码 | BOM | 换行 | 说明 |
|---|---|---|---|---|
| `.ps1`（含非 ASCII） | UTF-8 | **必须 BOM** | CRLF | PowerShell 5.1 无 BOM 时按 ANSI 解析，中文注释/字符串直接乱码甚至语法错误 |
| `.sh` | UTF-8 | **禁止 BOM** | LF | BOM（EF BB BF）会破坏首行 shebang（`#!` 前多了三个字节） |
| `.bat` / `.cmd`（含中文） | UTF-8 无 BOM | 否 | CRLF | 首行必须 `@chcp 65001 >nul`；或改用 GBK 保存（不推荐，统一 UTF-8） |
| Java/Kotlin/XML/MD/C++ | UTF-8 无 BOM | 否 | LF | IDE 默认 |
| 二进制（.so/.png/.zip/.apk） | — | — | — | `.gitattributes` 标 `-text`，禁止 Git 做任何转换 |

配套 `.gitattributes`（仓库根，必须提交）：

```
* text=auto
*.sh text eol=lf
*.ps1 text eol=crlf
*.bat text eol=crlf
*.png -text
*.so -text
*.zip -text
```

- 规则：**含中文的脚本，保存后必须用 `file <脚本>` 或读前 3 字节核验编码**（`EF BB BF` = BOM）。
- Windows 下用 Python 生成文件时，`open(..., 'w', encoding='utf-8')` **不写 BOM**；需要 BOM 用 `utf-8-sig`。

## 2. 构建与安装

- JDK：统一 JDK 17（`JAVA_HOME` 指向固定路径，如 `D:/dev-cache/jdk-17.0.20.1+1`）。
- 构建命令统一：`./gradlew :app:assembleDebug`（或 `gradlew.bat`），不在文档/脚本里散落其他任务名。
- **安装必须 `--abi arm64-v8a`**：模拟器（x86_64 镜像）经 ARM 转译运行引擎 so，不带 `--abi` 时包管理器可能选错 ABI，启动即 `UnsatisfiedLinkError`（EM_AARCH64 vs EM_X86_64）。
- 安装/调试脚本统一收敛到 `scripts/`（build/install/launch 一体，支持 `SERIAL`/`BUILD`/`LAUNCH` 环境变量），不要在会话里手敲一长串 adb 命令。
- ADB 路径统一由 `ADB` 环境变量或项目默认路径提供；脚本必须处理"无设备/多设备/未授权"三种状态。

## 3. 多进程与跨进程

- 引擎跑独立子进程（`:xxx` 后缀）时，**跨进程读 SharedPreferences 会读到陈旧副本**（MODE_MULTI_PROCESS 不可靠）：
  - 需要"实时"跨进程的少量状态 → 走 **Intent extra**（启动时传入，最可靠）或文件（JSON，读时即最新）；
  - 跨进程文件锁（如 SQLite）天然可用；
  - 确要用 prefs 跨进程：显式 `MODE_MULTI_PROCESS` 并接受毫秒级~秒级陈旧窗口，写明注释。
- 面板/浮窗等 UI 归属进程 = 视图合成发生的进程：SDL/NativeActivity 全屏 surface 会独占合成，Java 视图需走 **WindowManager 悬浮窗**（TYPE_APPLICATION + 显式 `gravity = TOP|START`，缺省 gravity 的 x/y 不按左上锚定）。

## 4. JNI / NDK

- **字符串上行禁止裸 `NewStringUTF`**：游戏文本编码不可控，非法 modified-UTF-8 会直接 abort。统一走 `NewByteArray` + `new String(bytes, "UTF-8")` 容错解码。
- 引擎线程回调 Java：`GetEnv` 失败即 `AttachCurrentThread`，用完 `DetachCurrentThread`；每次 JNI 调用后 `ExceptionCheck` 并清除。
- native 库的钩子/补丁代码：
  - 内部直调（intra-DSO `bl`）的函数 **GOT 补丁不可达**，只能内联跳板；跳板前必须校验被搬指令无 PC 相对编码（adrp/adr/b/bl/cbz/cbnz/tbz/tbnz/ldr-literal），不满足就拒绝挂钩（宁可不装也不崩）。
  - 代码页改写：mprotect RW → 写 → RX → `__builtin___clear_cache`。
  - 每个新挂点必须记录：目标符号（mangled）、所在内核/版本、序言校验结论、调用频率与线程——沉淀进项目规格表。

## 5. 资源与多语言

- 用户可见文案一律进 `strings.xml`，禁止硬编码在代码里（有硬编码检查任务的项目以检查为准）。
- 多语言项目（如 values / values-en / values-ja）**三语言必须同步增改**，默认语言（values）为文案源。
- 图标等资源替换后，所有密度档位（mipmap-mdpi..xxxhdpi、anydpi-v26）同步替换，不留旧档。

## 6. 版本管理与文档纪律

- 提交信息：`类型(范围): 摘要`（feat/fix/chore/refactor/docs），正文列要点；一个逻辑变更一个提交。
- 每次工作会话结束：更新进度文档、经验文档、待办文档（各项目对应文件见其专门规范），并提交。
- 里程碑打本地 tag（`git tag -a <名> -m <说明>`），不主动 push。

## 7. 通用工程习惯

- 脚本/工具优先做成可复用文件进仓库（`scripts/`），而非会话内一次性命令。
- 临时产物（截图/日志/中间文件）放固定临时目录并加入 `.gitignore`，不得混入提交。
- 新增依赖/新引擎/新内核前先查文档与经验文档，避免重复踩坑。
