# 游戏问题记录（按引擎 / 版本 / 内核索引）

本文件是**软件（App）侧的故障登记册**：哪个游戏、什么引擎、什么版本或内核、什么现象、根因在哪、怎么修的。

- 与 `MEMORY.md` 的分工：`MEMORY.md` 是**会话流水**（按时间线记踩坑，长度已超千行）；
  本文件是**按游戏/引擎维度的索引**（便于"这个游戏又出问题了，先查这里"）。
  同一条问题若已在 `MEMORY.md` 详细记录，本文件只留索引与结论，细节指向 `MEMORY.md`。
- 与内核仓库的分工：根因在**内核**（`artemis-compat/src/**`）的，这里只写"如何判断 + 结论 + 指向"，
  详细根因/修复见内核仓库 `docs/known-issues.md` 的对应条目（K-0XX）。
- **登记模板**（新增条目请照抄）：

## G-001 流星ワールドアクター · ARTEMIS(clean) · 画面全黑、只有声音

- **配置**：引擎 ARTEMIS；内核 `clean`；`art_engine_version=1`；`art_resolution` 未设（当时）
- **症状**：游戏正常启动、有 BGM/语音，画面全黑；日志刷 `lyc: image not found: hd/image/bg/black`
  等 71 条缺图
- **根因**：**内核侧 K-001** —— 自研内核「包优先、松散兜底」，官方是「松散优先」。
  该游戏是 PC rip：包内 `system/table/list_android.tbl` 指向真机高清资源（`hd/image/`、`pa/`），
  而 rip 只有 PC 资源（`image/`、`pc/`）；修正过的路径表以松散文件存在游戏目录
- **修复**：仅内核侧修复（K-001），App 无需改。**判定对照法**：把该游戏临时切 `official`
  → 若官方正常显示，即可判定为内核读取优先级问题，而非资源缺失
- **验证**：`image not found` 71 → 0；`draw[] drawn=47`；Girl's Blossom 无回归
- **状态**：已修
- **参见**：内核 `known-issues.md` K-001；`MEMORY.md` 2026-10-11 条目

## G-002 流星ワールドアクター · ARTEMIS · 画面超出屏幕、不自适应

- **配置**：引擎 ARTEMIS；内核 clean 与 official **皆有**；`art_resolution` 未设 → 后设 `1920x1080`
- **症状**：画面被裁切，上下 HUD 部分看不到（并非黑屏）
- **根因**：**App 侧**。引擎舞台取自游戏目录松散 `system.ini [ANDROID] WIDTH/HEIGHT = 1280x720`，
  而该游戏画布/美术是 1920x1080（`list_android.tbl` 里 `game_width=1920`、`game_scale={1920,1080}`）
  → 1920 画布塞进 1280 舞台再放大 1.5 倍 → 溢出被裁。
  App 本意是让 `[ANDROID]` 继承游戏 `[WINDOWS]`（`patchSystemIni` 确实写了 1920x1080），
  但每次启动的 `restoreAndroidSectionDefaults` 把 1920/1280/960 当"遗留值"删掉、回填缺省 1280x720
- **修复**：给该游戏设 `art_resolution=1920x1080`（App 官方路径：全局「设置 → 引擎管理 → Artemis 分辨率」，
  或单游戏覆盖）
- **验证**：stage 变 `1920x1080`，画面完整、上下 HUD 全可见
- **状态**：已修（**逐游戏配置**，非根治）
- **待办**：根治方案是让无覆盖时的默认真正继承游戏 `[WINDOWS]`（保留 `[WINDOWS]` 段，
  或不再把继承值当遗留值删）——尚未实施
- **参见**：`MEMORY.md` 条目 24 / 25

## G-003 （通用）ARTEMIS · official ↔ clean 切换 · 公共设置项消失

- **配置**：引擎 ARTEMIS；内核在 `official` 与 `clean` 之间切换（全局或单游戏）
- **症状**：一切到自研内核，Artemis 设置卡里"舞台分辨率 / 裁切铺满 / 图像缓存 / 字体缓存 / 省电"
  整块消失
- **根因**：**App 侧**。`app/src/main/java/com/tyranor/next/ui/settings/SettingsScreen.kt`（全局）与
  `PerGameSettingsScreen.kt`（单游戏）把这些**对两种内核都生效**的项错误地放进了
  `if (kernel == OFFICIAL)` 分支
- **修复**：把公共项提到分支外恒显；官方专属仅保留「引擎版本 + 自动补丁」；三语言
  `engine_settings_artemis_clean_hint` 文案同步改写
- **验证**：切自研内核后五项仍在；官方专属只隐藏两项
- **状态**：已修
- **规则启示**：判断某设置项属于哪个内核，要看**内核源码是否真的读这个键**，不要凭印象归类
- **参见**：`MEMORY.md` 2026-10-11 条目

## G-004 Japanese Version（Girl's Blossom Project）· ARTEMIS(clean) · 文本偏大、行距过紧

- **配置**：引擎 ARTEMIS；内核 `clean`；游戏用思源黑体（`font/sourcehansans-medium.otf`，字号 46）

- **状态**：已修
- **残留**：文本块整体仍比官方**高约 6 屏幕像素**（首行 baseline 取整差异），已量化未修
- **参见**：内核 `known-issues.md` K-002 / K-006

## G-005 流星ワールドアクター · ARTEMIS(clean) · 说话人名字显示成对白

- **配置**：引擎 ARTEMIS；内核 `clean`；该游戏名字用 Bold、正文用 Medium，**每句切一次 face**
- **症状**：名字标签里显示对白开头且笔画残缺（对白「はぁ、はぁっ。…」时标签显示「はぁ、はぁっ。」）
- **根因**：**内核侧 K-003** —— `LoadFont` 销毁字形图集页纹理，其它层的
  `TextGlyph::tex` 悬空，GL 复用纹理名后名字层采到对白字形
- **判定方法**：看内核日志 —— `tag[trace]: print {data=…}`（脚本给的）与
  `SetText[name]: … 'xxx'`（排版用的）内容都正确，说明问题在**渲染引用**而非文本来源
- **修复**：仅内核侧修复；此后内核会额外打 `print[name]` / `SetText[name]` / `glyph atlas watermark eviction` 便于排查
- **验证**：名字标签恢复为「無線」；淘汰计数 0；Girl's Blossom 无回归
- **状态**：已修
- **参见**：内核 `known-issues.md` K-003

## G-008 （Artemis 全系）ARTEMIS · 触摸模式手柄失效 + 两侧模式指示不一致

**三个症状（用户一次反馈）**：① 触摸模式下手柄完全不能用；② 手柄无法切到虚拟鼠标模式；
③ 刚进游戏时虚拟鼠标/触摸模式偶尔错乱，与右缘「点击模式」键的图标状态不一致。

- **配置**：引擎 ARTEMIS；内核 `clean`；模式持久化在 `shared_prefs/artemis_virtual_mouse.xml`
- **涉及实现**：`engine/.../akira/tyranoemu/remote/ArtemisLauncherBaseActivity.java`、
  `core/engine/EngineOverlayRouting.java`、`core/engine/EngineVirtualMouse.kt`、
  `core/ons/OnsExtractPanel.java`、`core/ons/OnsSideButtons.java`、
  `com/ies_net/artemis/ArtemisActivity.kt`

**根因（四个独立缺陷，叠在一起才出现三种表现）**

1. **触摸模式按键整体丢失**（症状①②）。Artemis 是 NativeActivity 直读输入，而本宿主加的
   覆盖窗（面板窗/光标窗/左右缘按键窗）**全是 `FLAG_NOT_FOCUSABLE`** → 触摸模式下没有任何
   窗口持焦 → 按键（手柄与键盘都一样）**Java 收不到、游戏也收不到**。
   实测判据：同一画面下 `input tap` 点 START 正常进游戏，而 `input keyevent/gamepad keyevent`
   一律零反应，`dumpsys window` 里 `mCurrentFocus` 却是 Activity 主窗口。
2. **`EmulateKeyEvent` 的 status 语义写错**（转发链全废）。内核
   `InjectHostKey(key, status)` 只按「`status == 0` = down、**非 0 一律 up**」入队；
   而 `ArtemisActivity.dispatchKeyEvent` 的映射表传的是 **`status = 2`** → 等于只发了一个 UP、
   永远没有 DOWN → 引擎看不到按下。
3. **右缘「点击模式」图标不跟手柄切换刷新**（症状③的一半）。`OnsSideButtons.clickModeButton`
   只在**创建时**和**点它自己**时更新图标；手柄快捷键（PANEL_MOUSE_TOGGLE / R2）走的是面板路径。
4. **启动时光标可见性不同步**（症状③的另一半）。宿主只把模式从 prefs 读回字段，
   而光标可见性在 `EngineVirtualMouse.cursorVisible`（初始恒 false）→ 「按钮显示鼠标模式、
   却没有光标」。三个宿主都有，**ONScripter 连初始化同步都没有**。
   另外侧键是在读 prefs **之前**创建的，图标会定格在字段初值。
5. 附带：Artemis 的 `routePanelKey` / `routeMouseKey` 调 `virtualMouse.handleKey` 时
   **漏了 `virtualMouseMode` 门控**（统一路由 `EngineOverlayRouting.routeKey` 有，这两处自建路由没有）
   → 触摸模式下面板一展开，按方向键/A 会被虚拟鼠标强行点亮光标并吞键。

**修复**

1. `applyMouseWindowFocusFlags` 改为**两种模式都让按键窗持焦**（面板展开时让给面板窗）；
   触摸模式保留 `FLAG_NOT_TOUCHABLE`，触摸仍然零干扰直达游戏；`setKeepNativeFocused(true)` 恒置。
   未消费的键由 `routeMouseKey` → `ArtemisActivity.dispatchKeyEvent` → 注入内核。
2. 新增 `tapEngineKey(engineKey)` = `EmulateKeyEvent(id, 0)` + 60ms 后 `EmulateKeyEvent(id, 1)`，
   替换映射表里 **31 处** `EmulateKeyEvent(id, 2)`；按住/松开的 `(140, 0/1)` 保持不变。
3. `OnsSideButtons.buildContainer` 把「刷新点击模式图标」的 Runnable 挂在根视图的 tag 上，
   暴露 `OnsSideButtons.refreshClickMode(root)`；`OnsExtractPanel.refreshClickModeButton()`
   在**手柄快捷键切换后**与**启动确定模式后**各调一次。
4. 新增 `EngineOverlayRouting.syncCursor(mouse, enabled)` 统一收口，三个宿主
   （Artemis `installVirtualMouseWindow` / Kirikiroid / ONScripter）在创建虚拟鼠标后调用；
   再补 `refreshClickModeButton()` 修正图标定格。
5. `routePanelKey` / `routeMouseKey` 的 `virtualMouse.handleKey` 前加 `virtualMouseMode &&`。
6. `EngineVirtualMouse` 增加 `needsRecenter` + `onSizeChanged`：窗口尚未 layout 时
   `ensureCursor` 会把光标算成 (0,0)，等布局完成后重新居中。

**验证（真机，流星ワールドアクター / clean 内核）**

| 项 | 判据 |
|---|---|
| 触摸模式按键恢复 | 游戏内发 `input gamepad keyevent 66` → 画面变化 + 内核日志 `onpush: key=13 -> setonpush_calllua` |
| 触摸模式下按键进 Java | 日志出现 `mouse catcher key code=…`（修复前为零） |
| 手柄切模式 | 触摸模式下发 R2(105) → `panel action mouse_toggle → virtual mouse ON`，prefs `false → true` |
| 模式与图标一致 | 鼠标模式启动：光标出现在画面中心 **且**右缘图标为箭头；触摸模式：无光标 **且**图标为手指 |
| 面板展开不误吞键 | `routePanelKey`/`routeMouseKey` 加门控后，触摸模式不再凭空点亮光标 |

**状态**：已修（已装 APK；内核无需改动）
**注意**：①「标题画面按任何键都没反应」是**游戏本身只认点击**，不是本 bug —— 判据要取游戏内对话；
② `setKeepNativeFocused` 在 clean 内核里没有符号（静默失败），但不影响渲染（鼠标模式下同样失焦且正常）。
**参见**：`docs/dev/剧情文本框手柄链路复刻方案.md`（面板链路）；本文件 G-005

## G-009 （通用）RENPY · 外置模块下载/安装入口找不到

- **配置**：引擎 RENPY；模块 `RenPy 8.5`（`cyou.joiplay.runtime.renpy.v8d4d1`）/ `RenPy 7.7.1`（`v7d7d1`），均未安装
- **症状**：用户反馈「renpy 模块无法开启，以前可以直接在里面下载对应模块安装，现在安装或导入入口都不存在」
- **排查**：下载链路其实**一直在**——引擎列表行右侧状态图标（小图标）点开「版本模块弹窗」，未安装条目点击直达
  下载页（`ExternalEngineLauncher.openInstallPage`，URL 自引入以来未变且实测 HTTP 200）。问题是**入口不可见**：
  行点击直达 Ren'Py 设置页，设置页里却没有任何安装入口；唯一入口藏在一个小状态图标后面。
- **根因**（App 侧 UI 可发现性）：`EngineSettingsDetailScreen` 的 RENPY 分支只有版本下拉 + 说明文字，无模块管理入口
- **修复**：
  1. `SettingsScreen.kt` 新增 `RenPyModuleManageCard`（RENPY 设置独立页内的「模块管理」卡片）：
     列出 8.5 / 7.7.1 两个模块的安装状态（`ExternalEngineLauncher.isPackageInstalled`），
     标注「当前使用」（按全局 `renpy_version` 解析），点击未安装模块打开下载页；
     ON_RESUME 自动刷新（装完 APK 返回即更新）。
  2. 引擎列表行点击语义**保持不变**（行 → 设置独立页；状态图标 → 版本弹窗）。
     曾试验「未安装时行点击改开下载弹窗」，用户否决：那样设置独立页就进不去了。
- **判定方法**：设置 → 引擎 → Ren'Py → 设置独立页应看到「模块管理」卡片；点未安装条目应拉起浏览器下载
- **验证**：真机 uiautomator dump 确认卡片与两个条目；点 8.5 条目拉起「打开方式」浏览器选择器
- **状态**：已修
- **教训**：功能"存在"不等于"可发现"——深层入口（小图标背后的弹窗）对用户等于不存在；
  新增依赖外置模块的引擎时，安装入口必须做进该引擎的设置独立页

## G-010 （通用 · 全引擎）· 手柄扳机键（R2/L2）绑定的动作不触发

- **配置**：引擎 ARTEMIS（其余引擎同样受影响）；手柄 Xbox 无线控制器（Model 1708，蓝牙）；
  面板动作 `PANEL_MOUSE_TOGGLE` 默认绑 R2
- **症状**：按 R2 切换触摸/虚拟鼠标无反应。日志证据：`getevent -l` 里按 R2 **只出现
  `EV_ABS ABS_GAS 000003ff→00000000`（轴量），没有任何 BTN 按键事件**；
  应用侧 `mouse catcher key code=…` 也从未出现 `code=105`
- **根因**（App/输入层）：该手柄的系统键位布局
  `/system/usr/keylayout/Vendor_045e_Product_02fd.kl` 把扳机**只映射为模拟轴**
  （`axis 0x09 RTRIGGER` / `axis 0x0a LTRIGGER`），系统永远不合成
  `KEYCODE_BUTTON_R2/L2` 键事件；而面板动作表 / 虚拟鼠标绑定表统一按 keyCode 匹配
  → 扳机绑定的动作全部失灵（呼出面板若绑 R2 同样失效）
- **修复**（App 侧，收口公共层）：新建 `engine/src/main/java/com/core/engine/TriggerAxisKeys.java`
  —— 对 `AXIS_GAS/AXIS_RTRIGGER → KEYCODE_BUTTON_R2`、`AXIS_BRAKE/AXIS_LTRIGGER → KEYCODE_BUTTON_L2`
  做 0.5 阈值的按下/松开**边沿检测**（按 deviceId 记状态），边沿处合成标准 KeyEvent；
  五个宿主（Artemis / Kirikiroid / ONS / Tyrano / RPGM）的
  `dispatchGenericMotionEvent` 最前端统一接入：合成键走 `dispatchKeyEvent` 完整链路
  （GamepadRemap → 面板动作表 → 虚拟鼠标 → 游戏），与真按键同权。
  **第二层根因（Artemis 特有，首轮修复遗漏）**：Artemis 的按键焦点在独立悬浮窗
  `mouseKeyCatcher`/`panelKeyCatcher` 上，手柄轴事件进的是这两个 View 而非
  `Activity.dispatchGenericMotionEvent`——View 树默认丢弃轴事件，Activity 层接了也收不到；
  二轮修复给两个 catcher View 各加 `dispatchGenericMotionEvent` override，
  与 Activity 共用 `routeMotionFromCatcher`（合成 + 面板吞轴 + 摇杆驱动光标）。
  手柄设置页 `GamepadSettingsActivity` 捕获绑定也接入了同样的合成（否则绑不上 R2/L2）
- **验证**：真机复测通过——按 R2 日志连续出现
  `trigger axis → synthetic key code=105` → `panel action mouse_toggle → virtual mouse ON/OFF`，
  触摸/虚拟鼠标来回切换正常，右缘图标同步
- **状态**：已修（真机验证）
- **规则启示**：手柄"某键没反应"先跑 `adb shell getevent -l` 看该键到底产生按键还是轴量；
  轴-only 的键必须由应用做轴→键合成，不能指望系统

## G-011 （通用）· ONS · 命名输入无输入框，直接用默认值继续

- **配置**：引擎 ONS；内核 onsyuri 0.7.7（libonsyuri，Android）
- **症状**：游戏要求输入名字/文本时没有输入框；脚本变量被设为默认值（常见为空串或空格），
  剧情直接继续，表现为“被空格占位符糊弄过去”
- **根因**：**内核侧**。`ONScripter::inputCommand()` 只读取参数、
  `setStr($var, default)` 后立即 `RET_CONTINUE`，没有 UI，也没有等待用户输入
- **修复**：内核新增跨平台接口 `ons_host_request_input(prompt, initial, maxlen, widechar,
  out, out_size)`（`ONSInput.h`，同步、UTF-8）；`inputCommand()` 只做编码转换 + 调接口 +
  写回变量。平台实现：Android 在 `onscripter_main.cpp` 通过 JNI 调
  `ONScripter.showInputDialog`（AlertDialog + EditText，条件变量等待，60s 超时）；
  Web 预留 `window.prompt`；桌面/无 UI 用 weak 默认返回 0。VNLingo `pluginVersion 4→7`
- **验证**：最小脚本 `input $0,"Name","",10,1`；真机对话框出现、中文输入、Enter 确认，
  日志 `confirmed=1 len=7`（UTF-8 14 字节 → GBK 7 字节），变量写回后剧情继续。
  ESG-13556 的 prompt 是长日文（脚本为 SJIS）；根因是 `readStr()` 返回共享
  `string_buffer`，保存 `desc`/`buf` 指针后再读会覆盖成空串；已改为读到即转
  `std::string`，并把提示从 window title 改到内容区 `TextView`。该游戏需
  per-game 编码选 `sjis`。实测直达输入场景后 TextView 正常显示长日文提示
  （native prompt_len=90 / Java promptLen=30）
- **状态**：已修（Android 真机；Web 未编译验证）
- **参见**：`PROGRESS.md` 会话七十三；ONS 仓 `dev` commit `6370bd5`

## 通用排查套路（跨游戏复用）

1. **先按引擎/内核分组定位**：同一现象在 official 与 clean 下是否都出现？
   - 只有 clean 出 → 大概率内核侧（查内核 `known-issues.md`）
   - 两者都出 → 大概率 App 侧或游戏资源/配置问题
2. **切内核做对照实验**：临时改单游戏覆盖，测完立即还原（本文件每条都记录了"判定方法"）
3. **看内核日志关键词**：`lyc: image not found`（资源/优先级）、
   `print: layer=…` / `SetText[name]`（文本层与字号）、
   `cache budgets` / `display: stage=`（设置是否生效）、
   `glyph atlas watermark eviction`（图集淘汰）
4. **像素级验证**：截图先用 PIL 打印 `im.size` 再换算坐标（横屏 2400x1080 与竖屏 1080x2400
   系数不同）；文本问题优先挑**静态、浅色背景**的场景（如标题/天空）做同句对照，
   带视差动画的场景无法做像素对齐
5. **手柄按键没反应**：第一步 `adb shell getevent -l` 看该键产生的是按键（BTN/EV_KEY）
   还是轴量（EV_ABS）——Xbox 等手柄的扳机在某些连接模式下只有轴量，系统不合成键码
   （G-010）；覆盖窗持焦的宿主还要确认轴事件有没有进 View 树（Artemis 教训）
