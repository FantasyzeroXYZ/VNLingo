# 2. 与参考的差距（要移植的）

| 编号 | 差距 | 参考实现 | 影响 |
|---|---|---|---|
| G1 | **还原路径丢失**：`deinflect()` 只返回 `List<String>`（去重后按字符串排序），丢掉 `score` 与 `conditions` | `deinflectWithPreprocess` 返回 `{term, rawSource, conditions, score}` 并按 score 排序 | 候选无法按深度排序（现在按字典序，浅层正确候选可能排后） |
| G2 | **无查表还原（table pack）** | `deinflection/packs/store.ts`：`meta` + `entries` 两 store，`lookupTableLemmas(lang, inflected)` O(log n) 单键查询；导入/删除/启停/内置包卸载与恢复 | 不规则活用（韩语/越南语等）只能靠规则，命中率低 |
| G3 | **表还原优先级未接入** | 参考 `tryMatchCandidate` 顺序：① term ② **reading（仅 ja）** ③ **查表还原（先于规则）** ④ 规则还原→term ⑤ 规则还原→reading | 有表包时仍走规则，候选质量差 |
| G4 | **非日语语言不跑预处理** | `deinflectWithPreprocess` 对所有语言跑 `descriptor.preprocessors` | 中文的全角英数/繁体→简体规范化不生效 |
| G5 | **规则覆盖面未核对**：ja 439 条 vs 参考 402 调用点 | 需逐组核对（含 `name` 与规则数） | 可能有遗漏/多余组 |
| G6 | **无「查询语言」设置**：语言由 `selectLang` 按脚本猜 | 参考以 `scope`（学习语言）贯穿：`skipReading = scope !== 'ja'`、语言包启停、词形还原器按 scope 创建 | 用户无法指定「我在查日语/英语/韩语」，多语言混排文本分派会出错 |
| G7 | **读音查询条件过窄**：仅当候选「含假名」才查 reading | 参考按 scope 决定（日语即查，不要求候选含假名） | 汉字词条按读音查不到（如用读音查汉字词） |
| G8 | **词典页语言筛选是纯客户端启发式**，与还原/查询无关 | 参考以词典 meta 的 `scope`（universal/ja/en/…）过滤，且字典元数据常驻 | 筛选与查询语言脱节；多种词典混装时无法按词典语言区分 |
| G9 | 无**查询测试/诊断**入口（看不到「哪条规则命中、走了几步」） | 参考 `dict.tsx` 的查询测试 + `onTrace` 追踪 | 还原质量无法验证与调优 |

# 3. 移植方案

## 3.1 M1：还原结果结构升级（G1）

**改动**：`OnsDeinflector` 新增结果类型并保留旧接口（兼容既有调用方）：

```java
public static final class Result {
    public final String term;          // 还原后的词典形候选
    public final String rawSource;     // 原始查询串
    public final List<String> conditions;  // 命中的条件链（还原路径）
    public final int score;            // 还原深度（越小越可信）
}

/** 新接口：带路径与深度，已按 score 升序；旧 deinflect() 保留为术语列表（内部调本方法）。 */
public static List<Result> deinflectDetailed(String query);
public static List<Result> deinflectDetailed(String query, String languageHint);
```

要点：

- 结果**按 score 升序**（参考 `sort((a,b)=>(a.score||0)-(b.score||0))`），同分按 term 字典序保证稳定；
- `conditions` 记录从输入到该候选的条件链（参考 `conditions: newConds`，逐步累积）；
- 缓存（现有 `sCache`）改为缓存 `deinflectDetailed` 结果，旧 `deinflect()` 由它派生，避免两份缓存；
- 调用方受益：候选列表排序更正确；Anki 的 `deinflection` 要素直接取路径字符串（`A→B→C`）。

## 3.2 M2：查表还原语言包（G2 + G3）

**新增** `engine/src/main/java/com/core/ons/deinflect/`：

| 文件 | 职责 |
|---|---|
| `DeinflectPackStore.kt` | 语言包元数据与条目存取（SQLite，复用词典库连接或独立库 `deinflect_packs.db`） |
| `DeinflectPackImporter.kt` | 导入 table 型包（JSONL/JSON：`[inflected, [lemma...]]` 数组），覆盖式导入 |
| `DeinflectLookup.java`(或 Kotlin) | `lookupTableLemmas(lang, inflected)`：单键查询，O(log n) |

**表结构**（对齐参考的两个 store）：

```sql
CREATE TABLE IF NOT EXISTS pack_meta(
  lang TEXT PRIMARY KEY, kind TEXT NOT NULL,        -- rules | table
  name TEXT, version INTEGER NOT NULL DEFAULT 1,
  enabled INTEGER NOT NULL DEFAULT 1,
  uninstalled INTEGER NOT NULL DEFAULT 0,           -- 内置 rules 型卸载标记（可恢复）
  entry_count INTEGER NOT NULL DEFAULT 0);

CREATE TABLE IF NOT EXISTS pack_entries(
  lang TEXT NOT NULL, inflected TEXT NOT NULL, lemmas TEXT NOT NULL,  -- JSON 数组串
  PRIMARY KEY(lang, inflected));
CREATE INDEX IF NOT EXISTS idx_pack_entries_lang ON pack_entries(lang);
```

**行为对齐**：

- 内置 rules 型（ja/en/ko）：默认启用；**卸载 = 打 `uninstalled` 标记**（数据在 assets，可零成本恢复）；
- table 型：导入后可启停、可删除；未安装 = 不参与查询；
- `lookupTableLemmas` 未启用/未安装/未命中一律返回 null（不抛错）。

**接入查询管线（G3）**：把 `OnsDictStore` 与 `OnsExtractPanel.tryMatchCandidate` 的候选匹配顺序改为参考顺序：

```
① term 精确
② reading 精确（按 §3.4 的语言判定）
③ 查表还原：对每个 lemma 查 term → 命中即返回（matchType = table-deinflect）
④ 规则还原 → term（按 score 升序试查）
⑤ 规则还原 → reading
```

命中后需记录 `matchType`（`term` / `reading` / `table-deinflect` / `deinflect-term` / `deinflect-reading`）
与 `deinflectionPath`，供面板显示与制卡填充（与 [设置项补全与交互改造方案.md](设置项补全与交互改造方案.md) 的 `deinflection` 要素对接）。

## 3.3 M3：全语言预处理（G4）

- `deinflectDetailed` 对所有语言执行该语言的 `preprocessors`（现仅 `lang.ja` 分支执行）；
- 预处理管线需按语言**执行**而非只存名字：当前 `deinflect_*.json` 只导出 `preprocessors: [名称]`，
  实现必须按名称映射到 Java 函数表：

| 语言 | 需要的预处理器 | 现状 |
|---|---|---|
| ja | 結合文字正規化 / 半角→全角 / 全角英数→半角 / 片假名→平假名 / 強調音畳み込み | 已实现 |
| zh | **全角英数→半角**、**繁体→简体**（参考用 `String.normalize('NFKC')`） | 未实现（仅存名字） |
| en / ko / vi | 无 | 无需 |

zh 的 NFKC 规范化在 Java 侧建议：`java.text.Normalizer.normalize(s, Form.NFKC)` +
必要时的繁体→简体映射表（参考仅用 NFKC，先按 NFKC 对齐，映射表列为可选增强）。

## 3.4 M4：查询语言设置（G6 + G7 + G8）

**新增设置**（沿用三级覆盖模型：全局默认 + 每游戏覆盖）：

| 设置项 | 取值 | 默认 | 作用 |
|---|---|---|---|
| 查询语言 | `自动` / `日本語` / `中文` / `한국어` / `English` / `Tiếng Việt` | 自动 | 决定词形还原用哪套规则、是否查读音、词典范围过滤 |
| 读音查询 | `开` / `关`（仅日语有效） | 开 | 对齐参考 `skipReading`；关闭后只查 term |
| 词形还原 | 开 / 关（已有） | 开 | 保持 |
| 查表还原 | 开 / 关（按语言包） | 随包启停 | 见 M2 |
| 词典范围 | 全部启用词典 / 仅当前词典（已有 scope 模型） | 当前优先 | 保持 |

**语言判定优先级**（`selectLang` 重写）：

```
1) 用户显式选择的查询语言（非「自动」）→ 直接采用
2) 每游戏覆盖 → 同上
3) 自动：按脚本判定（现有逻辑保留：假名/汉字→ja、谚文→ko、其余→en），
   但「汉字」需在 ja / zh 之间消歧：默认 ja（与参考 scope 行为一致），
   设置里可选择「中文优先」改变该默认
4) 读音查询按最终语言判定：仅 ja 查 reading（对齐参考 skipReading）
```

**词典范围过滤（G8）**：为词典元数据补 `scope` 字段（`universal` / `ja` / `zh` / `ko` / `en` / …），
导入时可由 `index.json` 的 `title`/语言字段或用户手选；查询时按「查询语言 + universal」过滤启用词典，
词典页的语言 chips 改为读该字段（保留现有启发式作为未标注词典的兜底）。

| 项 | 标准 |

| 规则完整性 | 五语言 JSON 与参考导出一致（ja 439 / en 40 / ko 124 / zh 0 / vi 0）；逐条 diff 为空 |

| 全语言预处理 | 中文模式下全角英数与 NFKC 变体可命中；日语预处理行为不变（回归） |
| 查询测试 | 测试界面能显示 matchedTerm / matchType / 路径 / 深度 / 释义组数，与 DiagLog 记录一致 |
| 回归 | 既有查词链路（点选非首单位字符、最长前缀、词形还原命中、制卡取词）不回归；词典页搜索与面板点选结果一致 |

# 6. 风险与约束

| 项 | 说明 |
|---|---|
| 性能 | 还原结果结构升级后，`deinflectDetailed` 需保持现有 LRU 缓存；候选数可能上升（score 排序不改变数量） |
| 跨进程 | 语言设置与语言包启停需 `MODE_MULTI_PROCESS` 或文件级共享（面板在引擎进程读、设置页在主进程写） |
| 兼容 | `deinflect()` 旧接口保留（返回术语列表），避免面板/词典页/测试工具同时改签名 |
| 词典 scope | 现有词典库无 `scope` 列：新增列 + 默认 `universal`，**不得因缺 scope 导致词典查不到**（未标注一律视为 universal） |
| 语言包存储 | 表型包体积可能较大，导入需事务 + 进度回调 + 失败不产生残库（沿用词典导入的既有约定） |
| 中文消歧 | 「汉字默认按日语」是现状也是参考行为；改为可配置需明确默认不变，避免影响现有日语用户 |
| 文档 | `README.md` 功能总览、`docs/guide/游戏内提取制卡功能方案.md` 与 MEMORY 的语言分派踩坑需同步 |
