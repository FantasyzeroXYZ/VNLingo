# 提取功能线设置项补全与交互改造方案

> 状态标记（纯文本）：已完成 ｜ 待完善 ｜ 未开始。
> 用途：自包含实施方案，可直接交给其他 agent 执行。
> 依据：参考项目 `D:\code\test-JavaScript\web game text` 的设置页实现
> （`node_modules/@trackreader/ui-assets/src/components/`：`containers/fields.tsx` 通用字段组件、
> `pages/settings/*` 各设置页、`pages/settings/anki/*` 制卡设置页）。
> **方向声明（重要）**：
> 1. **不合并设置页**——沿用现有页面划分（应用设置页 / 引擎设置页 / 每游戏设置页 / 制卡弹窗 /
>    翻译弹窗 / TTS 弹窗 / 面板设置弹窗 / 手柄设置页），**只做补全与交互对齐**；
> 2. **交互按参考实现**——分区（Section）＋行（Row：左标签右控件）＋下拉（Select）＋开关（Switch）
>    ＋滑块（Slider），**废弃「点行循环切换」这类交互**；
> 3. 字段映射采用参考的三级选择：**卡片方案 → 要素分组 → 「要素 → 下拉选模型字段」**；
> 4. **卡片类型只做两类：单词卡 / 句子卡**——参考的填空（cloze）与图片遮挡
>    （image-occlusion）**不移植**，对应要素（填空文本 / 背面补充 / 遮挡标记 / 标题 / 备注）
>    与视频要素（本项目无游戏内录屏）一并从要素表中剔除。

# 3. A 部分：engine 侧设置控件层（新增）

**新增文件**：`engine/src/main/java/com/core/ons/OnsSettingsWidgets.java`（纯 `android.view`）

|---|---|---|
| `SectionCard(Activity, String title, View... rows)` | 标题 + 圆角容器 + 行间分隔线 | 对齐参考 `Section`；替代现在散落的 `setTextSize(13)` 标题 |

| `hintRow(Activity, String text)` | 单行小字说明 | 替代散落的 `TEXT_DIM` TextView |
| `actionRow(Activity, String hint, ActionButton...)` | 提示 + 等宽按钮组 | 导入/导出/测试等 |
| `multiSelectDialog(Activity, String title, String[] labels, Set<String> selected, Consumer<Set<String>>)` | 多选对话框 | 方案要素勾选、批量删除选择 |
| `listItem(Activity, String title, String subtitle, View... actions)` | 列表项：标题 + 副标题 + 右侧动作按钮组 | 各类管理的列表行（对齐参考 `MappingProfileSection` 的列表项） |
| `sectionAction(Activity, String text, Runnable)` | 分区标题右侧的行动按钮（`＋` / `测试` / `导入`） | 对齐参考 `Section.action` |
| `emptyHint(Activity, String text)` | 空态提示（虚线框或灰字） | 列表为空时的引导（对齐参考「无配置」空态） |
| `confirmDialog(Activity, String title, String desc, Runnable onConfirm)` | 删除确认对话框 | 各类管理的删除确认（对齐参考删除确认弹窗） |
| `listItemActions(Activity, ActionSpec...)` | 列表项右侧图标动作组（应用/编辑/复制/删除） | 快捷键方案列表项（对齐参考 `ProfileSection` 的图标按钮组） |
| `captureCell(Activity, String label, String currentKey, Runnable onStartCapture)` | 键位单元格（显示当前键，点击进入录制） | 键盘/手柄网格（对齐参考 `ShortcutMapGrids` 单元格） |
| `segmentedTabs(Activity, String[] labels, int selected, Consumer<Integer>)` | 顶部子标签（如 键盘 / 手柄） | 网格子标签、信号类切换 |

**约束**：

- engine **不得**依赖 app 的 Compose（依赖方向 app → engine）；本层为纯 View；
- 视觉沿用现有常量（`TEXT_DIM` / `TEXT_BUTTON` / `dp()` / 圆角底色），与既有弹窗观感一致；
- 所有方法返回 `View`，调用方 `addView`，允许各弹窗**渐进迁移**（先制卡弹窗，后翻译/TTS/词典）；
- 管理视图（§6）以「纯 View 组件」形式实现并可与宿主解耦（例如 `DictManagerView`、
  `AnkiSchemeListView`），使**设置页弹窗、词典页、游戏内面板三处可复用同一实现**；
- 词典管理若需落到词典页（Compose），用 `AndroidView` 包裹该 View 组件即可，不在 Compose 侧重写一套。

## 4.2 字段映射改「要素 → 下拉」（核心改动）

**现状**（`OnsExtractSettingsDialogs.java:888-918`）：遍历**模型字段**，每行点按**循环 12 档槽位**。

**改为**（对齐参考 `Modals.tsx`）：

```java
// 1) 要素表：按卡片方案（单词卡 / 句子卡）取可映射要素
List<Element> elements = AnkiFieldElements.elementsFor(scheme);   // 见 §5.1

// 2) 每行：要素名 + 下拉（首项「未映射」+ 模型字段列表）
for (Element el : elements) {
    Spinner sp = new Spinner(activity);
    String[] opts = prependUnmapped(modelFields);                   // "未映射" + 真实字段
    sp.setAdapter(new ArrayAdapter<>(activity,
            android.R.layout.simple_spinner_dropdown_item, opts));
    sp.setSelection(indexOf(opts, fieldMap.get(el.key)));           // 反查当前映射
    sp.setOnItemSelectedListener(/* 写入 fieldMap[el.key] = 选中字段 */);
    container.addView(OnsSettingsWidgets.row(activity, el.label, sp));
}

// 3) 分组标题：单词 / 句子
```

**细节要求**：

1. **方向固定为要素 → 字段**（与参考一致），不再以模型字段为行主键；
2. 下拉首项固定「未映射」＝清空该要素映射；
3. 同一模型字段被多个要素选中时给出**冲突提示**（行尾警示 + 一键解除其余占用）；
4. 模型字段读取失败时，沿用现兜底（`Word/Reading/Meaning/Sentence`）保证可编辑；
5. **未连接 AnkiDroid 时保留上次字段列表**（本地缓存上次成功读取的字段数组），保证离线可编辑；
6. 切换卡片方案（单词卡 ↔ 句子卡）→ 载入该方案的要素集与已保存映射（对齐参考行为）；
7. 保存逻辑仍写 `AnkiCardConfig.setFieldMap`；i18n 新增键：`未映射`、两个分组标题（单词/句子）、冲突提示 2 条。

# 5. C 部分：设置项补全

## 5.1 卡片方案与要素表（制卡）

**卡片方案只做两类**（参考的填空 / 图片遮挡不移植）：

| **句子卡**（`sentence`） | 整句制卡 | `sentence` / `translation` / `sentenceAudio` / `source` / `image` / `translatedImage` |

**要素表**（`engine/src/main/java/com/core/anki/AnkiFieldElements.kt`，对齐参考 `element-catalog.ts`）：

| 分组 | 要素 key | 标签 | 单词卡 | 句子卡 |
|---|---|---|---|---|
| 核心 | `word` | 单词 | ✓ | |
| | `reading` | 读音 | ✓ | |
| | `definition` | 释义 | ✓ | |
| | `audio` | 单词音频 | ✓ | |
| 句子 | `sentence` | 句子 | ✓ | ✓ |
| | `translation` | 句子翻译 | ✓ | ✓ |
| | `sentenceAudio` | 句子音频 | ✓ | ✓ |
| 附加 | `source` | 来源 | ✓ | ✓ |
| | `wordTags` | 单词标签 | ✓ | |
| | `deinflection` | 词形还原 | ✓ | |
| 媒体 | `image` | 图片 | ✓ | ✓ |
| | `translatedImage` | 翻译图片 | ✓ | ✓ |

**明确不做**（写进文档以免后续被误加回）：

- 填空（cloze）与图片遮挡（image-occlusion）两类卡片；
- 对应要素：填空文本 `text` / 背面补充 `backExtra` / 遮挡标记 `occlusions` / 标题 `header` / 备注 `remarks`；
- 视频 `video`（本项目游戏内无录屏能力）。

**方案结构**（`AnkiCardSchemes`）：`{id, name, schemeType: word|sentence, elements[], deck, model, fieldMap{}}`；
`schemeType` 取代原方案中的 `cardType` 字段（**注意：不要沿用 `cardType` 命名，避免与已废止的三类型体系混淆**）。

**制卡出口**：按方案类型取要素集；必需要素缺失（单词卡缺 `word`、句子卡缺 `sentence`）时明确报错并引导到设置页（延续既有「禁止自建模型/捏造字段」契约）。

## 5.2 字段自动匹配（制卡）

新增 `engine/src/main/java/com/core/anki/AnkiFieldMatcher.kt`，移植参考别名表与归一化：

- 别名含**中英日**（`单词/単語`、`读音/よみ/読み`、`释义/意味`、`例句`、`翻译/翻訳`…）；
- 归一化：小写 + 去空格/下划线/斜杠/连字符；匹配顺序：精确别名 → 包含匹配 → 未映射；
- UI：字段映射区右上「自动匹配」按钮（`Section.action` 位置），只填充**未映射**要素，不覆盖用户手工值。

# 8. 验收标准

| 项 | 标准 |
|---|---|
| 字段映射 | 每个要素一行、右侧下拉可选任意模型字段或「未映射」；切换卡片方案（单词卡/句子卡）后要素集与映射随之切换；离线（未连接 AnkiDroid）仍可编辑上次字段列表 |
| 交互统一 | 全设置页无「点行循环切换」；多档项=下拉、布尔项=开关、连续值=滑块（与参考一致） |
| 方案 | 新建（名称+类型+要素勾选）/保存/加载/复制/删除/启用集合/回退链均可用；旧方案键升格且不丢映射；**只有单词卡与句子卡两类，无填空/遮挡入口** |
| 方案类型 | 两类方案的要素集正确（单词卡 12 项、句子卡 6 项）；必需要素缺失时制卡明确报错 |
| 制卡健壮性 | 五种失败场景各有文案与跳转；超时与重试可配；测试制卡可用 |
| 面板动作 | 自定义绑定即时生效；未自定义时与现版本逐键行为一致 |
| 推进方式 | `合成 Enter` / `合成方向键` 下，只认键盘的引擎可推进；`触点注入` 行为不变 |
| 设置页 | 各页 1:1 保留，仅新增分区/设置项；无页面合并；无 `ctx as Activity` 强转 |
| 六类管理 | **词典 / API / Anki 方案 / 字段映射组合 / TTS / 快捷键管理均可在设置页完成**：增删改、启用/激活、排序、测试、空态、删除确认齐备；同一管理在词典页与游戏内面板复用同一实现（数据与行为一致），面板不再保留重复实现 |
| 快捷键管理 | 快捷键方案可**保存/应用/编辑/复制/删除**；总开关关闭时其余快捷键设置隐藏；**信号测试**能显示实时按键来源与名称；**键位网格**按键盘/手柄子标签分组，点任意格子可录制并即时生效；手柄重映射、虚拟鼠标五动作、**面板动作**、引擎推进方式键位**同属一套方案快照**（不存在第二份 prefs） |
| 管理范式一致 | 六类管理的分区标题（含计数）+ 行动按钮、列表项（标题/副标题/动作组）、状态徽标、空态、编辑弹窗、删除确认、筛选/分页（组合类）形状一致；快捷键方案列表同样遵循该形状 |

**回归清单**：面板呼出/收起、词元选择、A 查词、X/Y 翻译与制卡、B 两步退出、音量键放行、听力模式、历史悬浮窗、候选切换、透明度、TTS 播放与自动朗读；制卡全链路（词卡/句卡+截图+语音）；kzaurauta（KRKR）与 ONS 各一款游戏提取不回归。

# 9. 风险与约束

| 项 | 说明 |
|---|---|
| 模块依赖 | engine 不得依赖 app 的 Compose；控件层必须纯 View |
| i18n | 新增文案三 locale 同步（engine 与 app 两处资源各自补键） |
| 数据迁移 | 方案结构升格需可回滚（保留旧键一版）；字段映射、deck/model 不得丢失 |
| 离线可用 | 字段映射编辑不得强依赖 AnkiDroid 连接（缓存上次字段列表） |
| 按键语义 | 面板展开「吞掉其余按键」与「音量键放行」为既有约定，改造后必须保持 |
| 合成按键 | §5.5 仅在面板收起时生效，需真机验证无双触发 |
| 方案范围 | **只做单词卡 / 句子卡**；后续若要加填空或遮挡，需先补要素表与 AnkiDroid 侧模型引导，禁止在本次改造中预留半成品入口 |
| 管理实现唯一性 | 六类管理**不得出现第二套实现**（现状：词典管理在词典页、API 在面板弹窗、制卡配置在另一弹窗）；统一为 engine 侧 View 组件 + 宿主嵌入，避免数据/行为分叉 |
| 跨模块嵌入 | 词典页为 Compose：嵌入 engine 的 View 组件需用 `AndroidView`；不得为复用而在 Compose 侧重写一套管理逻辑 |
| 文档 | `README.md` 功能总览与 `docs/guide/游戏内提取制卡功能方案.md` 需同步更新 |
