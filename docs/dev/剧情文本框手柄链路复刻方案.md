### Artemis 缺口（需决策）

真机实测：面板**收起**时按 RB，Java 侧**收不到任何按键**（NativeActivity 直读输入、焦点在 native
窗口），因此「手柄呼出面板」在 Artemis 上**不成立**——面板窗只有在展开后才可聚焦，形成
先有鸡还是先有蛋。解法只有一条路（二选一，需用户拍板）：

1. **常驻键捕获窗**：Artemis 下始终让键捕获窗持焦（与既有「虚拟鼠标模式」完全同路径），
   未命中面板动作的键再用 `super.dispatchKeyEvent` 转发给游戏映射链。代价：全按键改走
   `EmulateKeyEvent` 映射（虚拟鼠标模式已验证可用），**所有 Artemis 玩家都受影响**；
2. **保持现状**：Artemis 面板只经触摸（右缘按键）打开，打开后手柄快捷键照常可用（此路径
   代码已就绪，但本轮未测到面板打开状态，因为脚本点击没点中右缘按钮）。

在用户拍板前，保持现状（不擅自改动全部 Artemis 玩家的输入链路）。



**行为差异（有意，来自 §3.3 的默认绑定表）**：`PANEL_CONFIRM` 默认新增了 `ENTER` / `DPAD_CENTER`
（旧实现里这两个键在面板展开时被吞掉且不做事）；`PANEL_HISTORY` 新增动作但默认未绑键。

**给验收者的提示**：`adb logcat | grep "panel action"` 能看到面板实际消费了哪个动作；
面板展开时若游戏仍在推进，说明该引擎的按键绕过了 `dispatchKeyEvent`（Artemis 需确认
`panelKeyCatcher` 是否成功持焦，日志里 `panel focus flags failed` / `setKeepNativeFocused failed`
是失败信号）。

# 1. 参考实现拆解（四段链路）

## 1.1 上下文与屏蔽状态（谁在读手柄）

| 角色 | 位置 | 说明 |
|---|---|---|
| 游戏侧读取 | 游戏自身（MAIN world）调用 `navigator.getGamepads()` | 参考**无法阻止**它读，只能覆写该函数 |
| 扩展侧读取 | isolated world 的 `navigator`（独立对象） | 不受覆写影响，仍然读到真实按键 |
| 上下文标志 | `STATE.gamepadContext = 'game'`（进入游戏页时设置） | 决定 `gamepad.ts` 走哪个分支 |

## 1.2 呼出：面板关闭态只认 RB

`pollDictGamepad`（`dict-gamepad.ts:41-51`）：

```
面板关闭：
  if (edge(R1)) { emit('sdToggle'); return true; }   // 呼出面板并进入词典导航
  return false;                                      // 其余键照常注入游戏
```

关键细节（注释明确）：关闭态**只侦测 RB 的边沿，不改动其它键的 prevPressed 状态**——
因为该状态与游戏控制器共用，若在此同步会把游戏的按键按下态写进去、吞掉它自己的边沿检测
（症状：退出面板后按 A 不再推进游戏）。

## 1.3 焦点独占：MAIN world 覆写 `getGamepads`（本方案的技术核心）

`gamepad-block.ts` + `background.ts:gamepadBlockMain`（`971-1018`）：

- content script 把屏蔽状态经 `postMessage` 发给 MAIN world 的桥；
- 桥**覆写 `navigator.getGamepads`**，三种状态：

| 状态 | 行为 | 语义 |
|---|---|---|
| `enabled=true`（面板打开） | 返回 `pads.map(() => null)` | 保留数组长度、槽位填 null = 浏览器「手柄未连接」的表现，游戏读到全空 |
| `enabled=false` + `buttons=[词典键,截图键]` | 返回真手柄，但把 mask 内按钮的 `pressed/value` 归零 | 面板关闭时也屏蔽这两键，防泄漏 |
| `buttons=[]` | 原样透传 | 销毁/取消注入时恢复 |

- 屏蔽状态变更时**重发**（`_syncBlockMaskIfChanged`：词典/截图键配置变化即重发 mask）；
- 面板打开/关闭时 `setGamepadBlock(STATE.dictOpen)`；
- 注入幂等 + ACK 重发（防注入时序丢消息）。

## 1.4 面板打开后的快捷键（全量路由，本帧不注入游戏）

`pollDictGamepad`（`dict-gamepad.ts:52-70`），面板开启时：

| 手柄 | 动作 | 语义 |
|---|---|---|
| D-pad ↑ / ↓ | `sdUp` / `sdDown` | 换行 / 内容导航 |
| D-pad ← / → | `sdLeft` / `sdRight` | **选词** |
| A | `sdConfirm` | **确认查词** |
| B | `sdExit` | 退出（**两步**：先收释义，再收面板） |
| X | `sdTranslate` | **翻译整句** |
| Y | `sdFlashcard` | **触发制卡（词卡）** |
| START | `sdSentenceCard` | **句卡** |
| L1 / R1 | `sdScrollUp` / `sdScrollDown` | 释义滚动 |

补充规则（`gamepad.ts`）：

- 面板打开时**先松开按住的 D-pad 映射键与 Ctrl**（防卡键），再由面板导航接管；
- 面板打开时**丢弃非动作相位**（只认 DOWN 边沿）并消费全部按键；
- 未处理键位也要同步状态，避免退出时残留旧边沿；
- 弹窗（设置/退出确认/模式选择）有独立导航映射 `NAV_BUTTON_MAP`，**在任何上下文都可用**。

## 1.5 键盘与手柄同一套语义

`game-keyboard.ts`：键盘方向键 → `game:dictNav`；确认键 → `game:dictConfirm`；
制卡键 `f` → `dict:gamepad sdFlashcard`；翻译键 `t` → `sdTranslate`；
PageUp/PageDown → `sdScrollUp/sdScrollDown`。即**键盘与手柄共用同一套语义动作**。

# 3. 复刻方案

## 3.1 总体结构（对齐参考的四段）

```
① 呼出：面板关闭态只认「呼出键」（默认 RB），且不改动其它键的边沿状态
② 焦点独占：面板打开 → 手柄信号只进面板，游戏侧收不到
③ 面板快捷键：手语义动作表（可配置）→ 面板动作分发
④ 同一套语义：键盘与手柄共用同一动作表（含虚拟鼠标动作）
```

## 3.2 ② 焦点独占：Android 侧的三种手段（按引擎分层）

参考靠「覆写游戏读手柄的函数」实现，Android 侧没有等价物（游戏是 native 代码直接读 `input` 设备）。
因此按宿主的输入路径分三层实现，**优先级从高到低**：

### 手段 A：Activity 层按键／轴事件全吞（适用于按键经 `dispatchKeyEvent` 的宿主）

- 面板展开时，`panel.handleKey` 对**所有**按键（含未映射键）返回 true → 事件不达 `super`；
  当前 KRKR/ONS 已是此结构，需补的是**顺序修正**与**动作表化**（见 §3.4）；
- 摇杆轴：面板展开时 `dispatchGenericMotionEvent` 也必须前置判定并消费
  （现状：`virtualMouse.handleMotion` 在 `panel` 之后没有任何面板侧判定）；
- 要求：`panel.handleKey` 必须在 `virtualMouse.handleKey` **之前**（Artemis 现为反序，必须修）。

### 手段 B：native 焦点迁移（适用于 NativeActivity 直读输入，如 Artemis）

- Artemis 已有先例：`ArtemisActivity.setKeepNativeFocused(virtualMouseMode)`
  ——虚拟鼠标模式下让 native 失焦，覆盖层取得输入（`ArtemisLauncherBaseActivity:176/337`）；
- **面板展开时复用同一手段**：`setKeepNativeFocused(false)`（native 失焦）→ 按键由覆盖层/Activity 接收；
  面板收起且虚拟鼠标模式关闭时恢复 `true`；
- 需要验证：native 失焦后游戏是否仍能正常渲染与播放（前置经验：虚拟鼠标模式下已实测可用）。

### 手段 C：输入设备级兜底（可选，用于 native 仍能读到手柄的机型/内核）

- 若实测发现（B）下游戏仍响应手柄（native 直接 `poll` 输入设备），兜底手段：
  面板展开期间**关闭手柄按键的注入**或调用引擎侧的输入禁用开关；
- 该手段需逐引擎确认可用性，列为本方案的**待验证项**（§7），不作为首选。

### 验收口径（焦点独占的判定标准）

面板展开期间，用 DiagLog/日志记录「宿主收到并消费的按键」与「引擎侧实际动作」：

- 按 A/方向键/X/Y：面板动作生效，**游戏画面无任何推进/移动**（对照：面板收起时同样按键必须推进游戏）；
- 长按方向键后松开：退出面板时游戏不会出现「方向键卡住」或「连点」；
- 摇杆推动：面板打开时光标/选择不移动、游戏角色不移动。

## 3.3 ③ 面板快捷键：语义动作表（可配置）

**新增** `engine/src/main/java/com/core/ons/PanelActionBindings.kt`（与 `VirtualMouseBindings` 同款：
prefs 存 `action_<id>` → StringSet(keyCode)，`MODE_MULTI_PROCESS`，宿主 onCreate/onResume `refresh`，匹配走内存快照）。

| 动作 id | 语义 | 默认绑定（对齐参考） |
|---|---|---|
| `PANEL_TOGGLE` | 呼出/收起面板（**仅面板关闭态生效**） | RB（`KEYCODE_BUTTON_R1`） |
| `PANEL_TOKEN_PREV` / `NEXT` | 选词（←/→） | DPAD_LEFT / DPAD_RIGHT |
| `PANEL_NAV_UP` / `DOWN` | 内容滚动（↑/↓） | DPAD_UP / DPAD_DOWN |
| `PANEL_CONFIRM` | **确认查词**（未选词时回退播放） | A、ENTER、DPAD_CENTER |
| `PANEL_TRANSLATE` | **翻译整句** | X、T |
| `PANEL_CARD` | **制卡（词卡）** | Y |
| `PANEL_SENTENCE_CARD` | 句卡 | START |
| `PANEL_SCROLL_UP` / `DOWN` | 释义滚动 | L1 / R1 |
| `PANEL_EXIT` | 两步退出（先收释义→再收面板） | B、BACK、ESC |
| `PANEL_COPY` | 复制当前句 | C |
| `PANEL_PLAY` | 播放/重播语音 | SPACE |
| `PANEL_HISTORY` | 历史悬浮窗开关 | （新增，默认未绑定） |

**分发实现**：`handleKey` 由「switch(keyCode)」改为「查表 → 动作分发」（动作 → 面板既有方法），
未自定义时**行为必须与现版本逐键一致**（回归红线）。

**与虚拟鼠标动作的关系**：
`PANEL_CONFIRM` 与虚拟鼠标 `ACTION_CONFIRM` 默认同键（A），需定义**优先级**：
面板展开 → 面板动作优先；面板收起 → 虚拟鼠标动作（现有行为）。
`VirtualMouseBindings` 保持独立存储，但**同一个快捷键方案快照**同时包含两组（见 §3.5）。

## 3.4 ① 呼出与顺序修正

| 项 | 目标 |
|---|---|
| 呼出键 | 由硬编码 RB 改为 `PANEL_TOGGLE` 绑定（默认 RB），对齐参考「关闭态只认呼出键」 |
| 关闭态边沿处理 | **只侦测呼出键**，不改动其它键的边沿状态（防吞掉游戏按键，参考明确踩坑） |
| 宿主顺序修正 | `panel.handleKey` 提到 `virtualMouse.handleKey` **之前**（KRKR/ONS 已是；**Artemis 必须修**） |
| 摇杆处理 | 面板展开时在 `dispatchGenericMotionEvent` 最前端消费，且不驱动虚拟鼠标光标 |
| 音量键 | 保持放行（现有约定） |

## 3.5 与「快捷键方案」统一（与另一份方案对齐）

本方案的动作表并入 [设置项补全与交互改造方案.md](设置项补全与交互改造方案.md) §6.7 的
**快捷键方案快照**：

```
一个快捷键方案 = {
  gamepadRemap:   源手柄键 → 目标键
  virtualMouse:   五动作 → keyCode 集合
  panelActions:   本方案 §3.3 的 13 个面板动作
  engineAdvance:  各引擎推进方式（触点/合成 Enter/合成方向键/不动作）
}
```

即：呼出键、选词、查词、制卡、翻译、滚动、退出全部**可配置且随方案切换**，
不再分别维护多份 prefs。

## 3.6 ④ 键盘与手柄同语义

- `handleKey` 同时接收键盘与手柄事件（Android 侧二者都是 `KeyEvent`），本方案天然统一；
- 键盘侧的默认值直接取同一动作表（如 `PANEL_TRANSLATE` 默认含 `T` 键、`PANEL_CARD` 默认含 `Y` 手柄键），
  对齐参考「键盘 f/t 与手柄 X/Y 同一 `dict:gamepad` 契约」。

# 5. 验收标准

| 项 | 标准 |
|---|---|
| 呼出 | 面板收起时按呼出键（默认 RB）打开面板；改绑其它键后仍可呼出；呼出不影响游戏按键的边沿状态（退出面板后按 A 仍能推进游戏） |
| 焦点独占 | 面板展开期间：方向键只移动词元/滚动、A 只查词、X/Y 只翻译/制卡——**游戏画面零响应**；摇杆不驱动游戏；面板收起后全部恢复 |
| 快捷键 | 13 个动作全部可配置（捕获式）；未配置时与现版本逐键行为一致；键盘与手柄同语义 |
| 卡键 | 面板打开时若方向键处于按住态，先合成松开；退出面板后游戏不会「方向键卡死」 |
| 引擎覆盖 | KRKR（SDL Activity）、ONS、Artemis（NativeActivity 直读输入）三引擎均通过焦点独占验收 |
| 方案联动 | 切换快捷键方案后，呼出键/面板动作/虚拟鼠标动作/推进方式同时切换 |

# 6. 风险与约束

| 项 | 说明 |
|---|---|
| NativeActivity 输入路径 | Artemis 的按键不经 `Activity.dispatchKeyEvent`（既有实测注释）：手段 A 不足，必须用手段 B（native 失焦）；若确认 native 仍直读设备，再评估手段 C |
| 渲染副作用 | native 失焦需确认不影响渲染/音频（虚拟鼠标模式已实测可用，可复用其开关路径） |
| 边沿状态污染 | 关闭态**只能**处理呼出键，绝不写其它键的 prev 状态（参考明确踩坑，本项目也曾在别处踩过） |
| 音量键放行 | 面板展开时音量键必须继续放行（既有约定），动作表实现不得改变 |
| 默认行为回归 | P2 改动后，未自定义配置的逐键行为必须与现版本完全一致（回归红线，需逐键实测） |
| 多进程 | 动作表 prefs 需 `MODE_MULTI_PROCESS`（设置在 app 进程写、面板在引擎进程读） |
| 摇杆 | 面板展开时摇杆不得驱动虚拟鼠标光标；需在 `dispatchGenericMotionEvent` 前置消费并复位光标状态 |

# 7. 待验证项（实施前需真机确认）

| 项 | 验证方法 |
|---|---|
| 各引擎按键是否都经 `Activity.dispatchKeyEvent` | 面板展开后逐键测试并看日志（KRKR 经 SDL Activity 的按键路径已知；ONS/Artemis 的 native 路径按注释与实测复核） |
| native 失焦下手柄是否仍被游戏读取 | 面板展开时按住方向键 5 秒，看游戏是否移动/推进（Artemis 优先） |
| 摇杆是否经 `dispatchGenericMotionEvent` | 面板展开时推摇杆，观察光标与游戏 |
| 键盘事件是否与手柄同路径 | 面板展开时按 ←/→ 与手柄 D-pad 对比行为一致 |
